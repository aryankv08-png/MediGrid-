SYSTEM ARCHITECTURE SPECIFICATION

Request, message and update paths

Two stateless application nodes serve the console, dispatch, and control room. They never hold clinical state. Allocation happens through a conditional write against the bed records, and every accepted action is published to the message log in the same request that applied it.

⚡ IN-MEMORY RESILIENCE & SUB-MILLISECOND LOCKS

How Redis Powers MediGrid's 0 Double Allocations

In emergency medicine, two ambulances can never be granted the same ICU bed. Redis provides the high-speed first line of defense:

  • Atomic Mutex Locking: Uses SET lock:hospital:{id}:bed:{type} {token} NX EX 15 to serialize concurrent reservation requests in sub-millisecond memory before touching the database.
  • 15-Minute Expiry Countdown: Holds beds for exactly 900 seconds using Redis TTLs. If an ambulance crew diverts or cancels, the key expires automatically with zero orphan reservations.
  • Lua Script Safe Release: Releases locks safely by checking token ownership via Lua to prevent race conditions during network latency spikes.
  • Cross-Node WebSocket Fan-Out: Uses Redis Pub/Sub (ws:fanout) so events triggered on Node-1 immediately broadcast to ambulance crews connected to Node-2.

🐇 AMQP PRIORITY BUS & FAULT ISOLATION

How RabbitMQ Decouples Dispatches & Guarantees Delivery

Under severe emergency surges (e.g. city-wide disasters), database writes must never drop incoming calls. RabbitMQ provides rock-solid event decoupling:

  • Priority Queue Preemption (Priority 10 vs 0): Critical life-or-death ambulance requests are tagged with AMQP Priority 10. Even if 10,000 routine bed updates are queued, the broker dispatches the emergency bed request first!
  • Publisher Confirms: Every bed reservation is published using persistent confirm channels (channel.publish(..., { persistent: true })), ensuring zero message loss if a node crashes.
  • Choreographed Saga Engine: Coordinates multi-step patient transfers between hospitals (transfer.requested → accepted / rejected) with automatic compensating rollback.
  • Dead-Letter Queue (DLX): Any malformed message or unhandled consumer failure is automatically routed to medigrid.queue.dead_letter with one-click operator replay.
// RabbitMQ Priority Ingestion Channel
await channel.assertQueue('medigrid.queue.dispatch', {
  durable: true,
  maxPriority: 10,
  deadLetterExchange: 'medigrid.exchange.dlx'
});

Guarantees and how they are met
01

Zero double allocation

A bed leaves the free pool only through a conditional update that re-checks status = 'FREE' and a unique claim token. Two racing requests cannot both observe a win — the loser is refused, never queued on the same bed.

02

No lost events

The event is written in the same request that mutates the bed, so a broker outage delays delivery instead of dropping it. Stop the broker, keep working, restart it: the backlog drains in priority order.

03

Duplicate-safe

Every message carries an idempotency key (the bed-tracker recounts and reconciles against the durable MySQL primary). Redelivery cannot double-count a bed or double-book a patient.
